Chapter 01 · What it is

A system is only infrastructure once other people can build on it without asking you first.

Capsule is the organisation’s first design system: five written principles, six foundation areas, a token layer, twenty-five specified components and four platforms. It is documented twice over: as a Figma file engineers read, and as a written construction blueprint that states every value as a number.

Chapter 03 · The decision

Not another UI kit. A foundation for how we build.

A kit is a folder of components someone has to remember to open. A system is a chain of decisions where each layer only depends on the one above it, so a change enters once and arrives everywhere.

Five principles, written down

These settle arguments. They are quotable by someone who is not me, which is the only test that matters.

Chapter 08 · Design to development

The handoff is part of the system.

A handoff fails when the engineer has to infer a value. Capsule’s answer is that nothing is left to inference: sizes, padding, radii and state colours are written as numbers before anyone opens a ticket.

Chapter 09 · Governance

A living system needs a way to grow.

This is the half that decides whether a system is still true a year after launch, and the half where my evidence runs out. What is documented is marked as such; what isn’t, isn’t claimed.
